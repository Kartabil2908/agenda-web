1. Visão Geral e Atendimento às Instruções

O trabalho implementa uma Agenda Web full-stack com cadastro de contatos e compromissos, persistência em PostgreSQL, testes automatizados, containerização e deploy em nuvem.

Instrução do trabalhoComo foi atendida
Aplicação web completaBackend REST em Spring Boot e frontend em React.
CRUD e persistênciaCRUD de Contatos e Compromissos usando Spring Data JPA e PostgreSQL.
Versionamento e colaboraçãoGit, GitHub, branches por responsabilidade e revisão por Pull Request.
TestesTestes unitários de controllers, integração com PostgreSQL via Testcontainers e testes React com Jest.
CI/CDGitHub Actions executa testes, build e aceitação antes da publicação.
DeployRender Blueprint com PostgreSQL, backend Docker e frontend static site.
Correção de inconsistência: a entrega atual usa Render de forma consistente no código, na apresentação, no pipeline e na documentação.

Fluxo de uma requisição

  1. O usuário acessa o frontend publicado como Static Site no Render.
  2. O React chama a API pelo serviço api.js.
  3. O backend processa a requisição nos controllers REST.
  4. Os repositories acessam o PostgreSQL via JPA/Hibernate.
  5. A resposta JSON volta para o React atualizar a tela.

// Regra corrigida: não salvar contato inexistente private boolean resolverContato(Compromisso compromisso) { if (compromisso.getContato() == null) return true; Long contatoId = compromisso.getContato().getId(); if (contatoId == null) { compromisso.setContato(null); return true; } Optional<Contato> contato = contatoRepository.findById(contatoId); contato.ifPresent(compromisso::setContato); return contato.isPresent(); }
Resultado: o endpoint de compromissos retorna 404 quando recebe um contato vinculado que não existe, evitando inconsistência referencial.

// api.js normaliza localhost, URL completa ou host injetado pelo Render function resolveApiUrl() { const raw = process.env.REACT_APP_API_URL; if (!raw) return 'http://localhost:8080/api'; let url = raw.trim(); if (!/^https?:\/\//i.test(url)) url = `https://${url}`; url = url.replace(/\/+$/, ''); if (!/\/api$/i.test(url)) url = `${url}/api`; return url; }

11. CI/CD com GitHub Actions

CI/CD

O pipeline roda em push e Pull Request para a branch deploy. O papel do GitHub Actions é validar a entrega; o Render executa o deploy após os checks passarem.
